# 预制开发上下文（dev-context）使用说明

## 这是什么

在**任意项目根目录**创建 `.dev-context/` 目录，放入以下 Markdown 文件，AI 助手在开发时会优先读取这些文件作为上下文，避免每次开发都要口头重复交代，防止遗漏关键规范。

## 推荐的文件清单

| 文件 | 作用 | 建议内容 |
| --- | --- | --- |
| `技术文档.md` | 架构与实现说明 | 项目定位、技术栈、目录结构、核心模块、关键设计决策 |
| `开发规范.md` | 编码规范 | 命名约定、代码风格、注释要求、错误处理规范 |
| `构建规范.md` | 编译与构建 | **自动化脚本约定**、构建命令、产物目录、依赖管理、发布流程 |
| `开发进度.md` | 当前进度 | 已完成功能、进行中、待办、已知问题 |

> 文件名和数量不固定，任何 `.md` / `.txt` 文件都会被 `load_dev_context` 工具读取并合并返回。

## 一条强制规范：构建必须走脚本

凡需要**打包 / 编译 / 构建**的项目，必须提供自动化脚本，相关操作一律直接运行脚本，不得临时手敲命令。脚本统一放在项目根 `scripts/` 目录，见名知义（`build` / `package` / `publish` 等）。详见 `templates/构建规范.md`。

## 目录结构示例

```
你的项目/
├── .dev-context/
│   ├── 技术文档.md
│   ├── 开发规范.md
│   ├── 构建规范.md
│   └── 开发进度.md
├── src/
└── ...
```

## 开发流程建议（vibe coding）

AI 每次开工时按以下顺序调用工具，形成固定闭环：

1. `load_dev_context` —— 先读技术文档、规范、进度
2. `get_project_info` —— 识别语言、包管理器、目录结构
3. 改代码：`read_file` / `write_file` / `edit_file` / `search_files`
4. `install_deps` —— 装依赖（如有新增）
5. `run_lint` / `run_tests` —— 检查 + 测试
6. `diff_files` / `git_diff` —— 回看改动
7. `git_add` + `git_commit` —— 提交
